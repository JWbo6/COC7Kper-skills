# CoC记录与恢复
只定位用户指定的团和文件；结构化事实写 JSON/JSONL，叙事写 Markdown，日志只追加，不依赖固定模板。

1. 定位场次并读取版本号；用稳定 ID 区分团、角色、线索、NPC、地点、道具、骰子事件和后台演化事件。
2. 写入场次、状态、调查、角色变化和完整骰子数据；玩家视图过滤主持秘密、未发现线索和 `kp_only`。后台事件默认追加到 `01-模组资料/主持人资料/后台演化事件.jsonl`，后台快照写 `后台演化状态.json`，不把 KP payload 复制到玩家文件。
3. 后台恢复顺序为：读取后台快照→校验事件日志尾部和 event_id 幂等性→按 game_time/sequence 重建待处理事件和隐性状态→读取当前调查状态→生成玩家可知投影。场次记录可以引用后台事件 ID，但不得复制 `kp_only` 内容。
4. 写后重新读取校验。发现版本冲突、秘密过滤不确定、event_id 重复或 JSONL 损坏尾行时停止对应写入，隔离并报告，不静默丢失。
5. “继续上一场”恢复最后有效记录；“回顾/总结”明确输出玩家、角色私密或主持视图。最新有效事件优先于旧快照，但旧叙事只追加修正说明，不静默删除。

后台事件状态使用 `scheduled -> eligible -> fired`，必要时 `cancelled`。每条事件分离现实 `written_at`、记录发生时间 `occurred_at` 与模组内 `game_time`；按事件 ID或业务幂等键去重。

CoC7 规则基准：d100≤最终值成功，困难/极难为一半/五分之一向下取整；特殊模组规则单独标注。
