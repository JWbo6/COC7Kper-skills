# CoC 7 版判定速查

默认采用《Call of Cthulhu》第七版规则；若团内使用房规，先说明并在场次记录中标注。除非特别说明，所有百分骰结果均为 01-00，其中 00 表示 100。

## 基本技能检定

1. 以 `1d100` 与最终技能值比较：骰面不高于目标值为成功。
2. 最终目标值由基础技能、已分配的职业/兴趣技能、明确的临时修正组成；分别记录，不能把属性加值默认为技能值，除非本团已明确这种房规。
3. 普通成功：`roll <= skill`。
4. 困难成功：`roll <= floor(skill / 2)`。
5. 极难成功：`roll <= floor(skill / 5)`。
6. 大成功：通常为骰出 01；战斗中大成功还可能触发武器或规则规定的额外效果。
7. 大失败：技能值低于 50 时通常为 96-00；技能值 50 或更高时通常只有 00。特殊行动、战斗和房规可覆盖此判定，必须标注。
8. 结果等级按大成功、极难、困难、普通成功、失败、大失败排序；报告实际骰面、目标值、取整方式和成功等级。

## 奖励骰与惩罚骰

1. 普通 `1d100` 由一个十位骰和一个个位骰组成；十位骰的 0 表示 00，个位骰的 0 表示 0，因此组合为 00-09、10-19……90-00。
2. 每个奖励骰或惩罚骰额外掷一个十位骰；个位骰仍只掷一次。将所有十位结果分别与个位骰组合。
3. 奖励骰取对角色最有利的最终百分数；惩罚骰取最不利的最终百分数。多个奖励/惩罚骰按同一原则比较，不能当作加减百分比。
4. 完整记录个位骰、所有十位骰、候选结果、采用的最终结果及原因。

## 对抗检定

双方分别进行同一相关技能或属性检定，再比较成功等级：大成功高于极难，极难高于困难，困难高于普通成功，任何成功高于失败。双方等级相同时，通常由相关技能/属性更高者胜；若仍相同，按场景房规（通常平局对防守方或先声明的一方有利）处理并记录。

## 属性、对抗与修正

属性对抗、力量对抗和体格对抗应使用双方实际属性或规则给出的对抗表/难度，不把“属性加值”与技能值混用。临时优势或劣势优先转化为奖励骰/惩罚骰；只有明确来源的数值修正才直接加减目标值。

## 战斗与伤害

1. 先确定战斗轮、行动顺序、距离、目标和可用反应，再处理攻击、闪避、反击或其他行动。
2. 命中检定遵循对应战斗技能的成功等级；攻击者和防御者的对抗按战斗规则比较，不能跳过防御行动。
3. 命中后按武器伤害公式掷骰，再加入力量伤害加值等明确修正；记录武器、伤害骰、每个骰面、伤害加值、护甲吸收和最终伤害。
4. 记录重大伤害、倒地、濒死、死亡、穿刺或其他特殊效果。失败必须仍推进时间、位置、资源或危险，不用一次失败堵死唯一线索。

## 理智与疯狂

理智检定使用 `1d100 <= 当前SAN`：成功和失败分别采用模组或场景给出的理智损失区间。先掷损失骰，再根据规则更新当前 SAN；记录原始区间、实际骰面、损失值、旧值、新值，以及是否触发即时疯狂、总结性疯狂或其他疯狂处理。理智损失不得用普通技能成功等级替代。

## 幸运

幸运检定以当前幸运值为目标值。消耗幸运用于改变结果时，必须先向玩家说明消耗点数、改变后的结果和剩余幸运，得到明确确认后才能执行；记录消耗前后值、原因和对应 roll_id。幸运不能用于把失败改成大成功，具体限制按规则和房规执行。

## 明骰与暗骰

明骰公开骰面、修正、目标值、成功等级和结果。暗骰隐藏这些信息，只向玩家提供必要的叙事反馈；主持内部必须保存完整骰面、参数、判定和成功/失败后果。投骰前先确定成功与失败后果，再设置参数；投骰后不得为剧情方便改动目标值。

## 审计字段

每次掷骰至少记录：`roll_id`、`event_id`、`campaign_id`、`session_id`、`actor_id`、`purpose`、`visibility`、`formula`、`skill_value`、`difficulty`、`bonus_penalty`、`dice_faces`、`candidates`、`total`、`success_level`、`success_consequence`、`failure_consequence`、`execution_mode`、`provider`、`request_id`、`occurred_at`、`written_at`。暗骰同样完整记录，不能因玩家不可见而省略字段。
