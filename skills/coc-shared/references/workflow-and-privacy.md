# 工作流与信息隔离

## 路由优先级

1. 用户明确点名的 Skill 或明确命令。
2. 当前对话已锁定的主流程。
3. 高置信度意图：初始化、建团、车卡、主持、掷骰、记录、归档。
4. 只有在多团、重名、目标缺失或有安全冲突时询问。

每次只允许一个主流程 Skill 写入团状态；其他 Skill 作为被调用模块返回结构化结果。切换主流程前先保存当前草稿或说明未保存状态。

## 团状态机

`draft -> preparing -> active -> paused -> ending -> archived`。归档后默认只读。恢复归档必须创建新 revision 或新活动团，不覆盖原归档。

## 隔离矩阵

- KP 秘密：`01-模组资料/主持人资料/` 和内部状态，只给 KP 上下文。
- 玩家信息：`00-团务/玩家可知信息.md`，只能包含已公开事实、玩家角色已知内容和已发生结果。
- 原始模组：外部源只读保存路径和解析状态；新建团还必须在 `01-模组资料/原始模组/` 保存并校验团内副本。模组索引同时记录外部源与团内相对路径；不能把幕后段落复制到玩家文件。
- 角色私密背景：仅对应角色/玩家和 KP 可见。
- 归档清单：记录文件和哈希，但不把隐藏内容复制到公开摘要。

用户要求查看幕后真相时，说明该内容属于主持人秘密并拒绝泄露；可提供不剧透的玩家视角总结。

## 后台演化与公开投影

- 后台事件默认写入 `01-模组资料/主持人资料/后台演化事件.jsonl`，后台快照写入同目录 `后台演化状态.json`；这些文件属于 `kp_only`，不得复制到 `00-团务/玩家可知信息.md`。
- “后台发生”不等于“玩家知道”。只有玩家实际接触、看到/听到/测量到后果，或通过手机时间、车站时钟等可靠手段确认时间，才把独立的 `public_projection` 投影到玩家视图。
- 恢复团档时先恢复后台快照、按游戏内时间结算待触发事件和隐性状态，再读取/生成当前调查状态与玩家公开视图；不能用公开文件反推未公开真相。
- 后台事件的 `payload.kp_state` 与 `public_projection` 必须物理分离。公开后果可以进入场次叙事，但不能带出幕后因果、未接触的威胁进度或结局条件。
- 隐性事件若影响当前行动，只描述玩家能够感知到的结果；若没有感知手段，保持沉默并只更新 KP 状态。

## 写入与冲突

写入前读取目标并核对 revision。优先追加新事件；更新快照时使用临时文件、同卷原子替换和保留备份。遇到未知文件、同名目标、只读文件、路径越界或不一致 revision 时停止并报告，不静默覆盖。
