# 资料解析边界

- PDF：先尝试文本抽取；若正文过短、乱码严重或页面为图片，改用渲染/OCR，并在模组索引中记录 `parse_status` 和方法。
- DOCX：读取 `word/document.xml`；同时检查 `word/media/`，图片内文字需要 OCR/视觉读取。不要因正文乱码就覆盖原文。
- XLSX/XLSM：只读解析工作表、隐藏表、公式、数据验证、批注和保护信息。现有 `COC七版规则空白卡.xlsx` 是只读参考，不得改写、转成 CSV 或覆盖。
- Markdown/TXT/JSON/YAML：保留原始路径和内容哈希；先校验编码和结构，再建立索引。
- 所有源文件记录绝对路径、大小、mtime、哈希和解析时间。源文件只读，生成物写入团目录。
- 新建团时，`01-模组资料/原始模组/` 必须保存源文件副本；`sources[]` 应同时记录 `original_absolute_path`（外部原始文件）、`campaign_copy_path`（团目录内相对路径）、`copy_status`（`verified` / `pending` / `failed`）和 `sha256`。旧索引中的 `path`、`absolute_path` 字段继续保留兼容。副本必须位于团目录内，复制后重新计算哈希并与源文件一致；外部源不得移动、重命名或覆盖。
- 已存在的活动团可在外部源可用时继续恢复；缺少团内副本应作为迁移项报告，只有用户明确要求迁移时才增量复制，不得重建团目录或覆盖现有记录。

当前工作区的 `COC须知` 资料是既有资产；初始化、建团和车卡都不得移动、重命名、删除或覆盖它们。没有模组文件时，只报告待提供，不虚构解析结果。
